# Time-Based Blind SQL Injection in Library Search `q` Parameter

## Vulnerability Type
SQL Injection (Blind, Time-Based) - CWE-89

## Summary
The `q` GET parameter on the library/book-management search functionality is not sanitized before being used in a backend SQL query. Injecting conditional SQL logic via the `q` parameter causes a measurable response delay, confirming the input is concatenated directly into the query without parameterization. Since this endpoint is part of a CRUD-based book management system, the underlying query likely interacts with the same database used for book records (and potentially user/admin data), making this a viable vector for full data extraction.

## Vulnerable Endpoint
```
GET https://kzlabs.in/subdomains/library/index.php?q=
```

## Steps to Reproduce
1. Intercept the library search request in Burp Suite.
2. Send to Repeater/Intruder, marking the `q` parameter as the injection point.
3. Submit the payload below as the search query.
4. Observe a ~10 second response delay compared to the baseline (sub-second) response for a normal search term.
5. Re-send to confirm the delay is consistent and reproducible.
6. (Recommended follow-up) Since this is a CRUD interface, test whether other operations (add/edit/delete book) on this subdomain share the same unsanitized query pattern - if so, the injection surface extends beyond search.

## Request
```
GET /subdomains/library/index.php?q=1'XOR(94102*if(now()=sysdate(),sleep(10),0))XOR'Z HTTP/2
Host: kzlabs.in
Cookie: PHPSESSID=eku7qbgh4ve6ugik6eftsbautj
Referer: https://kzlabs.in/subdomains/library/
```

## Payload Used
```
1'XOR(94102*if(now()=sysdate(),sleep(10),0))XOR'Z
```

## Impact
- **Confidentiality:** Blind extraction of database contents - book records, and potentially user/admin credentials if tables are shared or joined - via time-based inference.
- **Integrity (if CRUD operations share the same flaw):** Could extend to unauthorized modification or deletion of book records if add/edit/delete endpoints are similarly unsanitized.
- **Severity:** High - unauthenticated/low-privilege access point, no user interaction required.

## Recommendations for Fix
1. **Parameterized queries/prepared statements** for the search query and all other CRUD operations (create, update, delete) on this module.
2. **Input validation** on the `q` parameter - restrict to expected search-term patterns and length.
3. **Audit all CRUD endpoints** in the library module for the same unsanitized-concatenation pattern, since this codebase shows a recurring habit of building SQL from raw input.
4. **Least-privilege DB account** so the web app's DB user cannot perform unintended operations beyond what each feature needs.
5. **WAF rule** to block SQLi patterns on this endpoint as an interim mitigation while the code fix is deployed.
