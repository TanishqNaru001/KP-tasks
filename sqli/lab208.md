# Time-Based Blind SQL Injection in Roll Number Parameter (Inventory/Results Portal)

## Vulnerability Type
SQL Injection (Blind, Time-Based) - CWE-89

## Summary
The "Roll Number" field on the CBSE Examination Results form is not sanitized before being used in a backend SQL query. Injecting conditional SQL logic via this field causes a measurable response delay, confirming the input is concatenated directly into the query without parameterization. Since this form is used to retrieve student examination results, the underlying query likely joins against a student records table, making this a viable vector for extracting sensitive student data (names, scores, admit card IDs, school details).

## Vulnerable Endpoint
```
https://kzlabs.in/subdomains/inventory/index.php
```

## Steps to Reproduce
1. Navigate to the CBSE Examination 2026 Results form at `/subdomains/inventory/`.
2. Enter the payload below into the **Roll Number** field only, leaving other required fields (Admit Card ID, School Number, Mother's Name) filled with normal/dummy values.
3. Check the "I have read and agree to terms of use" checkbox and click Submit.
4. Observe a ~10 second response delay compared to the baseline (sub-second) response for a normal roll number submission.
5. Re-submit to confirm the delay is consistent and reproducible.
6. Capture the request in Burp Suite (via proxy intercept) to document the exact POST/GET parameters and timing.

## Payload Used
```
1'XOR(94102*if(now()=sysdate(),sleep(10),0))XOR'Z
```

## Impact
- **Confidentiality:** Blind extraction of database contents is possible via time-based inference - potentially exposing student PII (names, roll numbers, marks, school details) given the context of this form.
- **Severity:** High - unauthenticated access point, no login required to reach this form, no user interaction needed from a victim.

## Recommendations for Fix
1. **Parameterized queries/prepared statements** for the Roll Number lookup query - never concatenate raw user input into SQL.
2. **Input validation** - enforce that Roll Number follows an expected numeric/alphanumeric format and length before it reaches the query layer.
3. **Least-privilege DB account** so the web app's DB user cannot access data beyond what this specific lookup requires.
4. **WAF rule** to block SQLi patterns on this endpoint as an interim mitigation while the code fix is deployed.
5. **Audit the other fields on this same form** (Admit Card ID, Mother's Name) individually, since they were tested together with Roll Number and should be confirmed clean or vulnerable in isolation.
