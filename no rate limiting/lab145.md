# No Rate Limiting on OTP Generation - Registration Endpoint

**Target:** `https://hackarena.site/subdomains/codeshackio/register.php`
**Vulnerability Class:** Missing Rate Limiting / Resource Exhaustion (CWE-307)
**Severity:** Medium
**Bypass Technique:** Header value fuzzing (`Accept-Language`) via Burp Intruder to evade fingerprint-based throttling

## Description

The registration endpoint sends an OTP to the user's email but enforces no rate limiting on how many times it can be requested. The request was sent to Burp Intruder with the payload position on the `Accept-Language` header. 15 requests were fired, and all 15 succeeded with no cooldown, CAPTCHA, or blocking.

## Steps to Reproduce

1. Intercept the OTP request on `register.php` and send it to Intruder
2. Set payload position on the `Accept-Language` header
3. Load a simple numeric payload list (1–15) and start the attack
4. Observe all 15 requests succeed with no throttling

## Impact

- Email bombing of any victim's inbox
- Unlimited OTP regeneration increases brute-force window
- Backend mail quota/cost exhaustion

## Remediation

- Rate-limit OTP generation per email/IP (e.g. 3–5 per 15 min)
- Enforce cooldown between consecutive requests
- Invalidate old OTPs when a new one is issued; cap to one valid OTP
- Return `429` once threshold is exceeded
- Key throttling on account identifier, not client-supplied headers
