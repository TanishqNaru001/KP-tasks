# Missing Rate Limiting on Two-Factor Authentication (2FA) Code Verification - Algolia

**Target:** `https://hackarena.site/subdomains/rate/`
**Vulnerability Class:** Missing Rate Limiting / 2FA Bypass via Brute Force (CWE-307)
**Severity:** Critical
**Bypass Technique:** OTP field fuzzing via Burp Intruder - unlimited verification attempts allow brute-forcing the 2FA code

## Description

The 2FA verification endpoint accepts unlimited OTP submission attempts with no rate limiting, cooldown, or attempt cap. Since typical OTPs are short (4–6 digits), the full keyspace can be brute-forced in a feasible number of requests, allowing an attacker to bypass 2FA entirely without ever receiving the legitimate code.

## Steps to Reproduce

1. Trigger the 2FA flow and intercept the OTP verification request in Burp Suite
2. Send the request to Intruder, set payload position on the OTP field
3. Load a numeric range payload (e.g. 0000–9999) and start the attack
4. Observe all attempts are processed with no lockout, delay, or blocking until the correct code is matched

## Impact

- Complete bypass of the 2FA control, defeating its purpose as a second authentication factor
- Full account takeover for any user whose first factor (password) is known or already compromised
- Automatable at scale against multiple accounts simultaneously

## Remediation

- Lock the account or session after a small number of failed OTP attempts (e.g. 3–5)
- Enforce a rate limit/cooldown per session/IP on verification attempts
- Invalidate the OTP after a short expiry window (e.g. 60–120 seconds) and after the max attempt count is reached
- Use a longer, higher-entropy OTP if feasible
- Return `429 Too Many Requests` once threshold is exceeded and log/alert on repeated failed 2FA attempts
