# Missing Rate Limiting on Contact Us Endpoint - UPchieve

**Target:** `https://hackarena.site/subdomains/limit/index.php#contact-section`
**Vulnerability Class:** Missing Rate Limiting / Resource Exhaustion (CWE-307)
**Severity:** Low–Medium
**Bypass Technique:** Payload fuzzing via Burp Intruder — the `Accept-Language` header and the `description` field are both usable payload positions, confirming the lack of throttling is not tied to one specific parameter

## Description

The "Contact Student Support" form sends a confirmation email on submission, but enforces no rate limiting on repeated submissions. The request was sent to Burp Intruder with the payload position set on the `Accept-Language` header. Repeated requests were fired, and each triggered a confirmation email with no cooldown, CAPTCHA, or blocking. The `description` field was also confirmed as a valid payload position, showing the missing throttling isn't scoped to a single parameter.

## Steps to Reproduce

1. Submit the contact form and intercept the request in Burp Suite
2. Send the request to Intruder, set payload position on the `Accept-Language` header (or the `description` field)
3. Load a simple payload list and start the attack
4. Observe repeated requests succeed with no throttling

## Impact

- Email bombing of any victim's inbox via forced contact submissions
- Backend mail quota/cost exhaustion
- No parameter-specific dependency means the flaw is systemic to the endpoint, not a single field

## Remediation

- Rate-limit contact form submissions per email/IP
- Enforce cooldown between consecutive requests
- Add CAPTCHA after a small number of attempts
- Return `429 Too Many Requests` once threshold is exceeded
- Apply throttling at the endpoint level rather than relying on any single request parameter
