# Missing Rate Limiting - Subscription Form (Yelp for Business)

**Target:** `https://hackarena.site/subdomains/rl-testing/`
**Vulnerability Class:** Missing Rate Limiting / Resource Exhaustion (CWE-307)
**Severity:** Medium
**Bypass Technique:** Header value fuzzing (`Accept-Language`) via Burp Intruder to evade fingerprint-based throttling

## Description

The subscription form endpoint does not enforce rate limiting on submissions. The request was sent to Burp Intruder with the payload position on the `Accept-Language` header. Multiple requests were fired in rapid succession, and all succeeded with no cooldown, CAPTCHA, or blocking.

## Steps to Reproduce

1. Intercept the subscription form submission request and send it to Intruder
2. Set payload position on the `Accept-Language` header
3. Load a simple numeric payload list and start the attack
4. Observe all requests succeed with no throttling

## Impact

- Spam/abuse of the subscription system at scale
- Potential resource exhaustion on backend (email/DB writes)
- Signals broader weak throttling architecture across the app

## Remediation

- Rate-limit form submissions per IP/session/account
- Enforce cooldown between consecutive requests
- Add CAPTCHA after a small number of attempts
- Return `429` once threshold is exceeded
- Key throttling on the actual identifier, not client-supplied headers
