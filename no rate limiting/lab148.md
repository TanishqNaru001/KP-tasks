# No Rate Limiting on User Registration & Email Enumeration - Courier

**Target:** `https://hackarena.site/subdomains/stress/index.php#register-section`
**Vulnerability Class:** Missing Rate Limiting + Email/User Enumeration (CWE-307, CWE-204)
**Severity:** Medium
**Bypass Technique:** Payload fuzzing on the email field via Burp Intruder — no throttling and differing responses leak account existence

## Description

The registration endpoint accepts unlimited submissions with no rate limiting. Additionally, the response differs based on whether the submitted email is already registered: an existing account returns an "account exists" message, while a new email is registered outright. This lets an attacker enumerate valid accounts at scale and mass-register unclaimed emails, with no cooldown, CAPTCHA, or blocking in place.

## Steps to Reproduce

1. Submit the registration request and intercept it in Burp Suite
2. Send the request to Intruder, set payload position on the `email` field
3. Load a list of email addresses and start the attack
4. Observe responses differ ("account exists" vs. successful registration) with no throttling across requests

## Impact

- Attacker can enumerate valid registered accounts for targeted phishing/credential-stuffing
- Attacker can mass-register arbitrary emails, potentially locking out legitimate users or spamming their inboxes with registration confirmations
- No throttling allows this to be automated at scale

## Remediation

- Rate-limit registration attempts per IP/session (e.g. 5–10 per 15 min)
- Return a generic response regardless of whether the email is already registered (e.g. "If this email isn't registered, you'll receive a confirmation link")
- Add CAPTCHA after a small number of attempts
- Return `429 Too Many Requests` once threshold is exceeded
- Require email verification before treating the address as claimed
