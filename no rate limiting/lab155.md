# Missing Rate Limiting on Resend Confirmation Email Endpoint - Yelp for Business

**Target:** `https://hackarena.site/subdomains/reset/`
**Vulnerability Class:** Missing Rate Limiting / Resource Exhaustion (CWE-307)
**Severity:** Low–Medium
**Bypass Technique:** Header value fuzzing (`Accept-Language`) via Burp Intruder to evade fingerprint-based throttling

## Description

The "Resend Email Now" button triggers a confirmation email but enforces no rate limiting on repeated clicks/requests. The request was sent to Burp Intruder with the payload position on the `Accept-Language` header. Repeated requests were fired, and each triggered a fresh confirmation email with no cooldown, CAPTCHA, or blocking.

## Steps to Reproduce

1. Trigger the "Resend Email Now" request and intercept it in Burp Suite
2. Send the request to Intruder, set payload position on the `Accept-Language` header
3. Load a simple payload list and start the attack
4. Observe repeated requests succeed with no throttling

## Impact

- Email bombing of any victim's inbox via repeated resend requests
- Backend mail quota/cost exhaustion
- Confirms throttling gap is systemic, not limited to one endpoint on this target

## Remediation

- Rate-limit resend requests per account/email/IP (e.g. 3–5 per 15 min)
- Enforce cooldown between consecutive resend requests
- Key throttling on the account identifier, not client-supplied headers
- Return `429 Too Many Requests` once threshold is exceeded
