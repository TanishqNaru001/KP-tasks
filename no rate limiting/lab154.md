# Missing Rate Limiting on Password Reset Endpoint - UPchieve

**Target:** `https://hackarena.site/subdomains/ratelimit/`
**Vulnerability Class:** Missing Rate Limiting / Resource Exhaustion (CWE-307)
**Severity:** Low–Medium
**Bypass Technique:** Header value fuzzing (`Accept-Language`) via Burp Intruder to evade fingerprint-based throttling

## Description

The password reset form sends a reset link to the submitted email, but enforces no rate limiting on repeated submissions. The request was sent to Burp Intruder with the payload position on the `Accept-Language` header. Repeated requests were fired, and each triggered a fresh reset link email with no cooldown, CAPTCHA, or blocking.

## Steps to Reproduce

1. Submit the password reset form and intercept the request in Burp Suite
2. Send the request to Intruder, set payload position on the `Accept-Language` header
3. Load a simple payload list and start the attack
4. Observe repeated requests succeed with no throttling

## Impact

- Email bombing of any victim's inbox via repeated reset requests
- Backend mail quota/cost exhaustion
- Multiple valid reset links outstanding at once increases the attack window if a link is intercepted or leaked

## Remediation

- Rate-limit reset requests per email/IP (e.g. 3–5 per 15 min)
- Enforce cooldown between consecutive requests for the same email
- Invalidate previously issued reset links when a new one is generated
- Key throttling on the account identifier, not client-supplied headers
- Return `429 Too Many Requests` once threshold is exceeded
