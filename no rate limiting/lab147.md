# No Rate Limiting on Partner Authentication Endpoint - On Running

**Target:** `https://hackarena.site/subdomains/security-test/index.php`
**Vulnerability Class:** Missing Rate Limiting / Brute Force (CWE-307)
**Severity:** High
**Bypass Technique:** Password field fuzzing via Burp Intruder — no lockout or throttling on failed login attempts

## Description

The partner login page at `/subdomains/security-test/index.php` does not enforce any rate limiting or account lockout on authentication attempts. The login request was sent to Burp Intruder with the payload position set on the `password` field. Repeated requests with varying password values were submitted, and all were processed with no cooldown, CAPTCHA, or blocking observed.

## Steps to Reproduce

1. Submit a login attempt on the partner authentication page and intercept the request in Burp Suite
2. Send the request to Intruder, set payload position on the `password` parameter
3. Load a wordlist and start the attack
4. Observe repeated failed login attempts are accepted with no throttling or lockout

## Impact

- Enables brute-force/credential-stuffing attacks against partner accounts
- No lockout means automated tools can attempt unlimited passwords per account
- Successful brute force leads to full account takeover of partner accounts

## Remediation

- Enforce account lockout or progressive delays after a small number of failed attempts (e.g. 5)
- Rate-limit login requests per account/IP
- Add CAPTCHA after repeated failures
- Return `429 Too Many Requests` once threshold is exceeded
- Log and alert on abnormal login attempt volume for a single account
