# Missing Rate Limiting on Newsletter Subscription Endpoint - Nextcloud

**Target:** `https://hackarena.site/subdomains/throttle/`
**Vulnerability Class:** Missing Rate Limiting / Resource Exhaustion (CWE-307)
**Severity:** Low–Medium
**Bypass Technique:** Header value fuzzing (`Accept-Language`) via Burp Intruder to evade fingerprint-based throttling

## Description

The newsletter subscription form sends a confirmation email on submission, but enforces no rate limiting on repeated submissions. The request was sent to Burp Intruder with the payload position on the `Accept-Language` header. Repeated requests were fired, and each triggered a subscription email with no cooldown, CAPTCHA, or blocking.

## Steps to Reproduce

1. Submit the newsletter subscription form and intercept the request in Burp Suite
2. Send the request to Intruder, set payload position on the `Accept-Language` header
3. Load a simple numeric payload list and start the attack
4. Observe repeated requests succeed with no throttling

## Impact

- Email bombing of any victim's inbox via forced newsletter subscription
- Backend mail quota/cost exhaustion
- Possible abuse as a spam relay against third-party inboxes if email input isn't tied to session ownership

## Remediation

- Rate-limit subscription submissions per email/IP
- Enforce cooldown between consecutive requests
- Add CAPTCHA after a small number of attempts
- Return `429 Too Many Requests` once threshold is exceeded
- Key throttling on the email/account identifier, not client-supplied headers
