# Rate Limit Too Lenient on Password Reset Endpoint - WakaTime

**Target:** `https://hackarena.site/subdomains/request/index.php#reset-section`
**Vulnerability Class:** Insufficient Rate Limiting (CWE-307)
**Severity:** Low–Medium
**Bypass Technique:** Header value fuzzing (`Accept-Language`) via Burp Intruder to evade fingerprint-based throttling

## Description

The password reset form sends reset instructions to the submitted email, but the rate limiting in place is too lenient to meaningfully restrict abuse. The request was sent to Burp Intruder with the payload position on the `Accept-Language` header. Repeated requests were processed and reset emails kept arriving with minimal to no effective cooldown.

## Steps to Reproduce

1. Submit the password reset form and intercept the request in Burp Suite
2. Send the request to Intruder, set payload position on the `Accept-Language` header
3. Load a simple numeric payload list and start the attack
4. Observe repeated requests succeed and reset emails continue to arrive with no meaningful throttling

## Impact

- Email bombing of any victim's inbox via repeated reset requests
- Backend mail quota/cost exhaustion
- Weak throttling suggests the control can be bypassed elsewhere using the same header-fuzzing technique

## Remediation

- Rate-limit reset requests per email/IP with a stricter, enforced threshold (e.g. 3 per 15 min)
- Enforce a real cooldown between consecutive requests for the same email
- Key throttling on the account identifier, not client-supplied headers
- Return `429 Too Many Requests` once threshold is exceeded
