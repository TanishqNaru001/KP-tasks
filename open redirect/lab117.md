# Open Redirect - Tumblr

**Target:** `https://kzlabs.in/subdomains/sso/`
**Vulnerability Class:** Open Redirect (CWE-601)
**Severity:** Low–Medium
**Bypass Technique:** Backslash + `@` userinfo trick (`\@`) to defeat substring/domain-prefix validation

## Description

The `/subdomains/sso/` endpoint handles SSO logout and accepts a `redirect_to` parameter specifying where to send the user after logging out. Legitimate use redirects to a Tumblr page (e.g. `https://www.tumblr.com/dashboard`). However, the validation appears to only check that the string `tumblr.com` appears somewhere in the `redirect_to` value (likely via a naive substring or prefix check), rather than properly parsing the URL's host.

By crafting a URL of the form `https://www.bing.com\@www.tumblr.com`, the `\@` sequence is interpreted by browsers as URL "userinfo" syntax (`user@host`), meaning `www.bing.com` is treated as the userinfo and `www.tumblr.com` becomes... actually the browser parses everything before `@` as credentials and everything after as the host - but with normalization quirks around backslashes (`\` is often treated as `/` by browsers), this can cause the browser to navigate to `bing.com` instead of `tumblr.com`, while still passing a backend check that only looks for the substring `tumblr.com`.

## Steps to Reproduce

1. Copy a legitimate SSO logout link:
   ```
   https://kzlabs.in/subdomains/sso/?action=logout&redirect_to=https://www.tumblr.com/dashboard
   ```
2. Modify the `redirect_to` parameter to:
   ```
   https://kzlabs.in/subdomains/sso/?action=logout&redirect_to=https://www.bing.com\@www.tumblr.com
   ```
3. Load the crafted URL in a browser
4. Observe the browser logs the user out and redirects to `bing.com`, despite `tumblr.com` still appearing in the parameter value

## Impact

- **Post-logout phishing:** users are most vulnerable to credential-harvesting right after being logged out (they often re-enter credentials on whatever page loads next) - an attacker can chain this into a convincing fake Tumblr/SSO login page
- **Validation bypass confirms a broader pattern:** if `redirect_to` is checked via substring matching rather than proper URL parsing, other bypasses (extra subdomains, encoded characters, different backslash/slash combinations) are likely also possible
- **Trust abuse:** the link uses a legitimate-looking SSO/logout flow on `kzlabs.in`, increasing victim trust compared to a bare external link

## Remediation

- Parse `redirect_to` as a proper URL and extract the actual host component (not substring matching) before validating
- Validate the parsed host against an exact allowlist (e.g. `www.tumblr.com`, `tumblr.com`) rather than checking if the string is merely *present* in the parameter
- Strip or reject userinfo syntax (`user@host`) in redirect targets entirely - legitimate redirects should never need it
- Normalize backslashes to forward slashes (or reject them outright) before parsing, since browsers do this silently and validation must match browser behavior
- Add an interstitial confirmation page before redirecting off-domain, especially post-logout
