## Title
Stored HTML Injection - Romit Wallet Transfer Platform

## Vulnerability Type
Stored HTML Injection

## Summary
The Romit wallet transfer platform at `https://hackarena.site/subdomains/transfer/index.php` is vulnerable to Stored HTML Injection through the **Nickname** field.

The application stores the supplied HTML and later includes it in wallet invitation emails. The injected HTML is rendered by the recipient's email client instead of being displayed as plain text.

## Vulnerable Endpoint

**Application:**

`https://hackarena.site/subdomains/transfer/index.php`

**Injection Point:**

**Settings → Profile Settings → Nickname**

**Affected Functionality:**

**Share Your Wallet → Send Wallet Invitation**

## Vulnerable Field

| Field | Injection Location | Trigger Location |
|---|---|---|
| Nickname | Account Settings → Profile Settings | Wallet invitation email |

## Steps to Reproduce

### Step 1 - Access the application
1. Navigate to:

   `https://hackarena.site/subdomains/transfer/index.php`

2. Log in to the application.

### Step 2 - Navigate to Profile Settings
1. Open **Settings**.
2. Locate the **Profile Settings** section.
3. Identify the **Nickname** field.

### Step 3 - Inject HTML into the Nickname field
1. Enter the following payload into the **Nickname** field:

   ```html
   <a href="https://bing.com">Click me</a>
   ```

2. Click **Save Changes**.

### Step 4 - Send a wallet invitation
1. Navigate to the **Share Your Wallet** section.
2. Enter a recipient email address.
3. Click **Send Wallet Invitation**.

### Step 5 - Verify HTML Injection
1. Open the wallet invitation email received by the recipient.
2. Observe that the injected HTML is rendered as HTML instead of plain text.
3. The injected content appears as a clickable **"Click me"** link.

## Payload Used

```html
<a href="https://bing.com">Click me</a>
```

## Impact

- Attacker can inject HTML content into wallet invitation emails.
- Injected links can be used for phishing or redirects to malicious websites.
- The content may appear to originate from the legitimate application.
- Other user-controlled fields in email templates may be affected similarly.

## Recommendations for Fix

1. HTML-encode the **Nickname** before inserting it into the email template:

   ```php
   htmlspecialchars($nickname, ENT_QUOTES, 'UTF-8');
   ```

2. If HTML is required, sanitize user input using a trusted HTML sanitization library and allow only safe HTML tags and attributes.

3. Review other profile fields and email templates for the same issue.
